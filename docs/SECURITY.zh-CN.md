# 安全策略

## 支持版本

`sharp` 当前处于 1.0 之前。除非明确维护发布分支，安全修复会直接应用到主分支。

## 报告漏洞

请不要在公开 issue 中直接披露疑似漏洞细节，应先让维护者有机会进行评估。

推荐流程：

1. 通过 GitHub 提交[私密漏洞报告](https://github.com/gkmz/sharp/security/advisories/new)。审核期间只有报告者和仓库维护者能够访问。
2. 提供简洁描述、受影响命令或工具及版本、复现步骤和潜在影响。
3. 不要提交真实生产环境密钥、token 或敏感数据；应尽量使用最小化测试数据。

如果 GitHub 私密报告表单暂时不可用，可以创建一个最小化的[公开 issue](https://github.com/gkmz/sharp/issues/new/choose)，请求维护者提供私密沟通渠道。不要在该 issue 中包含漏洞细节、利用代码、密钥或敏感数据。

## 安全范围

通常属于范围内的问题：

- 命令执行或文件访问超出用户意图。
- 参数、输出、日志或剪贴板路径中不安全地处理密钥。
- 解析器在不可信输入下导致进程崩溃。
- 对 `sharp` 有实质影响的依赖漏洞。

通常不属于范围的问题：

- 工具按设计回显用户输入。
- 无效输入返回错误时导致的错误结果。
- 用户 shell 环境或 `sharp` 外部剪贴板提供方的漏洞。
